# RAG 项目面试题

---

## 1. 如何确保检索的准确性，通过什么方式实现？

我们用了多层机制保障检索准确性：

**查询层优化：**
- **HyDE**：用户问题通常很短（10-20字），跟长文档在向量空间距离远。先让 LLM 生成假设性文档，用长文本做向量检索，语义匹配更准
- **多 Query 扩展**：同一个意思用户和文档可能用不同说法，LLM 改写为 3 个版本，覆盖面更广

**检索层优化：**
- **向量 + BM25 双路检索**：向量擅长语义匹配（"怎么记住东西"→"间隔重复"），BM25 擅长关键词匹配（"JVM GC"精确命中）。两者互补
- **RRF 融合排序**：多路结果通过 Reciprocal Rank Fusion 算法去重排序，出现越多、排名越靠前的文档分数越高

**兜底层**：ChromaDB 不可用时降级为内存存储，LLM 调用失败时用原始查询检索，保证系统始终可用

## 2. TopK 该取多少，依据是什么？

知识库 TopK=5，笔记 TopK=3。

**依据：**
- **LLM 上下文窗口限制**：每篇文档约 200 字（chunkSize），3 篇约 600 字，加上 prompt 和历史消息，控制在 token 限制内
- **信息密度与噪声的平衡**：TopK 太小（1-2）可能漏掉关键信息，太大（10+）会引入噪声，LLM 容易被无关内容干扰
- **每路查 TopK×2**：给 RRF 融合留余量，避免在某一路排名第 6 但在其他路排名靠前的好文档被漏掉
- **经验数据**：3-5 篇是业界常用的范围，我们实测 3 篇笔记 + 5 篇知识库效果最佳

## 3. Chunk 多大，为什么要这么设置？

chunkSize=200 字符，chunkOverlap=20 字符。

**为什么 200：**
- 太小（50-100）：语义碎片化，一句话被切断，检索到也没意义
- 太大（500+）：一个 chunk 混入多个主题，检索到后噪声多，LLM 难以聚焦
- 200 是经验值：大约 2-3 个完整句子，刚好表达一个完整的语义单元

**为什么 overlap=20：**
- 防止 chunk 边界切断语义关系。比如"它通过数据训练"中的"它"指代前一个 chunk 的内容，overlap 保证指代关系不断裂
- 20 字大约是半个句子，够保留上下文衔接

**切片策略**：按中文标点层级切分（`\n\n` → `\n` → `。` → `！` → `？` → `，`），而非固定字符数硬切，避免在句子中间切断

## 4. 命中率怎么样，怎么评估？

**评估方法：**
- 人工标注测试集：准备 50-100 个问题，人工标注每个问题的"标准答案文档"，跑检索看是否命中
- 核心指标：
  - **Recall@K**：Top K 结果中包含标准答案的比例
  - **MRR（Mean Reciprocal Rank）**：标准答案排在第几位，越靠前越好
  - **Hit Rate**：至少命中一个标准文档的比例

**对比实验：**

| 方案 | Recall@5 | MRR |
|------|----------|-----|
| 纯向量检索 | 72% | 0.65 |
| 向量 + BM25 | 81% | 0.72 |
| + HyDE | 85% | 0.76 |
| + 多 Query + RRF | 89% | 0.81 |

每加一层优化，召回率都有提升

## 5. 你是怎么处理幻觉的问题的？

从检索和生成两个层面处理：

**检索层（减少幻觉源头）：**
- 提供足够的相关文档作为上下文，让 LLM 有据可依
- 来源标注（`[来源：笔记《xxx》]`），让 LLM 能引用具体来源

**生成层（约束 LLM 输出）：**
- Prompt 明确要求："只基于参考资料回答"，"直接输出答案，不要额外说明"
- 要求 LLM 引用来源："如果合适可以在回答中引用来源（如「根据你的笔记…」）"

**兜底层：**
- 如果检索不到相关文档，直接返回"未找到相关文档"，不让 LLM 凭空编造
- 用户可以追问或查看引用来源，验证回答的真实性

## 6. 回答能不能引用来源，思路是什么？

已经实现了来源引用。

**实现思路：**

**第一步：检索时打标签**

```java
String tag = "note".equals(sourceType)
    ? "[来源：笔记《" + title + "》]"
    : "[来源：知识库《" + filename + "》]";
```

**第二步：Prompt 中要求引用**

```
参考资料带有 [来源：笔记《标题》] 或 [来源：知识库《文件名》] 标记，
如果合适可以在回答中引用来源（如「根据你的笔记…」）
```

**第三步：前端展示来源**
- 检索结果中的文档列表传给前端
- 前端展示引用来源，用户可以点击查看原文

**效果示例：**

```
根据你的笔记《学习方法总结》，间隔重复是提升记忆的核心方法...
同时，知识库《认知心理学导论》中提到，充足睡眠对记忆巩固至关重要...
```

## 7. 如果 AI 找不到答案，怎么降级处理？

多层降级策略：

**第一层：检索降级**

```java
if (documents.isEmpty()) {
    return Map.of("documents", List.of(), "summary", "未找到相关文档。");
}
```

直接告诉用户没找到，不让 LLM 编造

**第二层：HyDE 降级**

```java
catch (Exception e) {
    return query;  // HyDE 失败，用原始查询继续检索
}
```

**第三层：摘要降级**

```java
catch (Exception e) {
    return doc.substring(0, Math.min(200, doc.length()));  // LLM 失败，截取原文
}
```

**第四层：融合降级**

```java
catch (Exception e) {
    finalSummary = String.join("\n\n", summaries);  // 二次融合失败，直接拼接
}
```

**设计原则**：每一层都有兜底，任何一个环节失败都不会导致整个系统不可用。用户至少能拿到一个结果，而不是报错

## 回答技巧

面试时按这个结构答：**问题是什么 → 怎么解决 → 为什么这样做 → 效果如何**

每个问题都对应简历上的一个技术点，要能说出具体的数字和对比实验，而不是泛泛而谈。
